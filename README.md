# Учебный проект «Библиотека»

Консольное приложение на C# / .NET 10 демонстрирует выдачу и возврат книг,
ограничение количества активных выдач и обработку исключений. Данные хранятся
только в памяти и заново создаются при каждом запуске. Метод `Save()` имитирует
сохранение: настоящий файл `library.db` не создаётся.

## Структура

- `Library.App/Models/Models.cs`: книги, читатели, записи выдач и статусы книг.
- `Library.App/Data/InMemoryLibraryRepository.cs`: четыре книги, читатели Анна
  (ID 1) и заблокированный Борис (ID 2); поиск и имитация сохранения.
- `Library.App/Services/LibraryServices.cs`: класс `LibraryService`, выдача,
  возврат и поиск книги по точному названию.
- `Library.App/Exceptions/`: базовые и предметные исключения.
- `Library.App/Program.cs`: последовательность демонстрационных сценариев
  и обработка ошибок.
- Корневой `Program.cs`: запускает ту же демонстрацию через
  `Library.App.Program.Main()`.
- `Library.Tests/LibraryServiceTests.cs`: тесты правил выдачи, возврата,
  поиска и отката при ошибке сохранения.
- `Library.App/Models/Result.cs`: результат регистрации (`IsSuccess`, `Error`).
- `Library.Tests/LibraryServicesTests.cs`: тесты регистрации читателя,
  проверки входных данных, назначения ID и отката при сбое сохранения.

## Анализ исходного проекта

Приложение выдаёт следующие строки:

```text
--- 1. Анна берёт книгу 1
OK
--- 2. Анна снова берёт книгу 1
Ошибка: Книга уже выдана
Выберите другую книгу
--- 3. Несуществующий читатель 99
OK
--- 4. Заблокированный Борис берёт книгу 2
OK
--- 5. Анна берёт книги 2 и 3
OK
--- 6. Анна берёт четвёртую книгу
Ошибка: Превышен лимит книг
Сначала верните одну из книг
```

Неверные `OK` в сценариях 3 и 4 объясняются тем, что `LoanBook` возвращал
`-1` и `-2`, а вызывающий код игнорировал результат. Для отсутствующей книги
аналогично возвращался `-3`. Повторная выдача и превышение лимита использовали
обычный `Exception`, а `Program` определял причину сравнением текста сообщения.
Сервис дополнительно печатал ошибку и выполнял `throw ex`, теряя исходную
часть стека вызовов. `ReturnBook` скрывал любые исключения, а поиск по названию
использовал исключение для обычной ситуации «не найдено».

## Исправленная логика

`LoanBook` теперь возвращает `void`: успешное завершение означает выдачу,
а ошибка выражается исключением. Проверки выполняются до изменения данных
в следующем порядке: наличие читателя, блокировка, наличие книги, статус
книги, лимит активных выдач. Поэтому при нескольких нарушениях сообщается
первое из них.

| Ситуация | Решение (что принимает) | Почему |
| --- | --- | --- |
| Пустое имя при регистрации | `Result.Fail(string error)` с сообщением об имени | Ожидаемая ошибка ввода: вызывающий код проверяет `IsSuccess` и показывает `Error`, данные не меняются. |
| Пустая почта или почта без `@` | `Result.Fail(string error)` с сообщением о почте | Проверка выполняется до создания читателя и сохранения; исключение для исправимого ввода не нужно. |
| Успешная регистрация | `RegisterReader(string? name, string? email)` возвращает `Result.Ok()` без аргументов | Успех сообщается только после добавления читателя в репозиторий и успешного `Save()`. |
| Читатель заблокирован | `ReaderBlockedException(int readerId)`, код `reader_blocked` | Блокировка запрещает новую выдачу; ID позволяет указать конкретного читателя. |
| Книга не найдена при выдаче | `BookNotFoundException(int bookId)`, код `book_not_found` | Выдать отсутствующую книгу нельзя; отдельный тип позволяет предложить проверить номер. |
| Книга уже выдана | `BookAlreadyLoanedException(int bookId)`, код `book_already_loaned` | Повторная выдача нарушает правило доступности книги. |
| Достигнут лимит активных выдач | `LoanLimitExceededException(int readerId, int limit)`, код `loan_limit_exceeded` | Исключение содержит читателя и предел; сначала нужно вернуть одну из книг. |
| Читатель не найден; книга не найдена при возврате | `NotFoundException(string entityName, object key)`, код `not_found` | Универсальный тип сообщает, какая сущность и по какому ключу отсутствует. |
| Активная выдача не найдена при возврате | `LoanNotFoundException(int readerId, int bookId)`, код `loan_not_found` | Читатель и книга существуют, но нет невозвращённой выдачи этой книги этому читателю. |
| Сбой хранения при регистрации, выдаче или возврате | `DataAccessException(string message, Exception? inner)`, код `data_access_failed`; `Save()` передаёт исходный `IOException` вторым аргументом | Техническая ошибка отличается от ошибки ввода; `InnerException` сохраняет причину и стек, изменения в памяти откатываются. |
| Поиск по названию: совпадений нет | `FindByTitle(string title)` возвращает `null` через `FirstOrDefault` | Отсутствие результата поиска — обычная ситуация; вызывающий код проверяет `null`. |
| Поиск по названию: книга найдена | `FindByTitle(string title)` возвращает `Book` | Точное совпадение названия позволяет получить книгу без изменения её состояния. |
| Общий контракт ошибок приложения | Абстрактный `AppException(string errorCode, string message, Exception? inner)` | Хранит код, сообщение и вложенное исключение; служит базой для ошибок приложения. |
| Общий контракт нарушений правил библиотеки | Абстрактный `DomainException(string errorCode, string message)` | Объединяет предметные исключения под общим типом `AppException`. |
| Непредвиденная ошибка | Завершающий `catch (Exception ex)` в `Program` принимает любое оставшееся исключение | Сообщает об ошибке и позволяет демонстрации перейти к следующему сценарию. |

Все четыре новых исключения наследуются от `DomainException`, который
наследуется от `AppException`. Исключения содержат ID соответствующей сущности;
ошибка лимита также содержит установленный предел.

`LoanNotFoundException` также наследуется от `DomainException` и содержит
`ReaderId` и `BookId`. `ReturnBook` ищет активную выдачу через `FirstOrDefault`;
если её нет, выбрасывает это исключение. Отсутствующий читатель или книга
при возврате приводят к `NotFoundException`.

`DataAccessException` наследуется непосредственно от `AppException`, принимает
сообщение и исходное исключение вторым аргументом. `Save()` вызывает
`WriteToStorage()` внутри `try`, перехватывает только `IOException` и оборачивает
его в `DataAccessException`. Исходное исключение доступно через `InnerException`.

У читателя может быть не более трёх невозвращённых книг. Книга выдаётся на
14 дней от текущей локальной даты. После возврата запись остаётся в истории
с `IsReturned = true`, книга становится доступной, и место в лимите освобождается.
Заблокированный читатель может вернуть ранее взятую книгу, но не взять новую.
Возврат проверяет, что активная выдача принадлежит указанному читателю.

Сервис не печатает сообщения. `Program` обрабатывает каждый новый тип отдельным
`catch`, а также обрабатывает `NotFoundException`, `LoanNotFoundException`, `DataAccessException`
и непредвиденные ошибки. `OK` появляется только после успешного завершения
сценария. Если `Save()` выбрасывает исключение, сервис восстанавливает состояние
в памяти и повторно выбрасывает исходное исключение через `throw;`.

В `catch (DataAccessException ex)` выводится `ex.ToString()`: полный текст
включает вложенный `IOException`, стек вызовов и строку исходного кода
в `WriteToStorage`, где произошёл сбой.

`FindByTitle` использует `FirstOrDefault`: возвращает книгу при точном совпадении
названия или `null`, если совпадения нет.

## Регистрация читателя через Result

`RegisterReader(string? name, string? email)` проверяет, что имя не пустое
и не состоит из пробелов, а почта не пустая и содержит `@`. Это минимальная
проверка по условию задания, без полной проверки формата адреса. Ошибка ввода
возвращается как `Result.Fail(...)`: `IsSuccess = false`, `Error` содержит
объяснение. При ошибке читатель не добавляется и `Save()` не вызывается.

При корректном вводе создаётся `Reader` с ID `n + 1`, где `n` — текущее
количество читателей. Начальные и конечные пробелы имени и почты удаляются.
Читатель передаётся в `repo.AddReader(reader)`, затем вызывается `repo.Save()`.
После успешного сохранения возвращается `Result.Ok()` (`IsSuccess = true`,
`Error = null`). Если сохранение завершается ошибкой, читатель удаляется
из списка, а `DataAccessException` передаётся вызывающему коду.

Пример использования:

```csharp
var result = service.RegisterReader("Виктор", "victor@example.com");
Console.WriteLine(result.IsSuccess ? "OK" : result.Error);
```

При исходных двух читателях Виктор получает ID 3. Формула `n + 1` соответствует
заданию и предполагает последовательные ID без удаления ранее зарегистрированных
читателей. Регистрация проверяется тестами; сценарии `Main` остаются прежними.

## Запуск

Требуется .NET SDK 10. Из корня проекта:

```powershell
dotnet run --project Task1Week6.csproj
```

Ту же демонстрацию можно запустить напрямую:

```powershell
dotnet run --project Library.App/Library.App.csproj
```

Корневой проект исключает вложенные исходники из собственной компиляции
и ссылается на `Library.App`, поэтому оба варианта используют одну реализацию.

```text
--- 5. Анна берёт книги 2 и 3
OK
--- 6. Анна берёт четвёртую книгу
Сначала верните одну из книг
--- 7. Анна берёт несуществующую книгу 99

--- 8. Анна возвращает книгу 1
OK
--- 9. Анна берёт книгу 4 после возврата

--- 10. Анна повторно возвращает книгу 1

--- 11. Поиск книги CLR via C#
Найдена книга: CLR via C#
OK
--- 12. Поиск несуществующей книги
Книга не найдена
OK
--- 13. Ошибка сохранения при возврате книги 2
Ошибка сохранения: Не удалось сохранить данные библиотеки.
```

После последней строки печатается полный `DataAccessException` с вложенным
`System.IO.IOException: Диск недоступен: не удалось записать library.db`.
Пути, номера строк и оформление стека зависят от сборки и среды запуска.
Сценарий 13 включает `SimulateStorageFailure` на время возврата и затем
отключает его в `finally`; неудачный возврат откатывается.

В конце книги 2, 3 и 4 выданы Анне, книга 1 доступна. У Анны четыре записи
в истории выдач, из которых три активны. Сценарии выполняются автоматически,
ввод с клавиатуры не требуется.

## Проверка

```powershell
dotnet test Library.slnx
```

Тесты проверяют успешную выдачу и срок возврата, четыре новых исключения,
отсутствующего читателя, лимит и его освобождение, повторную выдачу после
возврата, ошибочные возвраты, возврат чужой книги, поиск и восстановление
состояния после сбоя сохранения при выдаче и возврате.

`LibraryServicesTests` дополнительно проверяет успешную регистрацию и удаление
пробелов, пустые имена (`null`, пустая строка, пробелы, табуляция), пустую почту
и адреса без `@`, последовательное назначение ID, вызов сохранения, откат
регистрации при сбое хранилища и успешную повторную попытку.

Проверено: оба варианта запуска используют одну демонстрацию. Все 28 тестов
проходят; сборка решения с `-warnaserror` завершается без ошибок и предупреждений.
